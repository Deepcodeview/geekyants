🎯 The 4-Step Candidate Journey (Simple & Clear)

No boring book-format jargon. Here is how the platform actually works in real life:

1

Intake & Skill Gap Detection AI Powered

The company's HR system (Workday, Greenhouse) sends the Job Description and candidate resume. The platform compares both and calculates skill gaps (e.g. "Candidate is strong in Java/MySQL, but lacks Kafka streaming experience").

2

Unique Project & Private GitHub Repo Automated

AI generates a tailored architecture blueprint (REQ-001..004, REST endpoints, data entities). The platform automatically provisions a private GitHub repository, commits working starter code, and invites the candidate for a 7-day development test.

3

Zero-Race Commit Freeze & CI Grading Tamper-Proof

When the candidate submits (or when time expires), their write permission is revoked immediately, the HEAD commit SHA is tagged, and platform-owned hidden tests run inside an isolated Docker sandbox container.

4

12–15 Code-Tailored MCQs & Final Score Anti-Cheating

The AI reads the candidate's exact code commits and creates 12–15 questions directly citing their classes and methods. The candidate takes a timed test, and a weighted 4-factor hiring scorecard (35% Reqs, 25% Tests, 15% Code, 25% MCQs) is generated.

👨‍💻 How I Built This: Architectural Decisions & Tech Stack

Explain exactly why you chose each technology in an interview or technical presentation:

☕

Why Java 21 & Spring Boot 4.1? Core Framework

I chose Java 21 for Immutable Record Classes (making DTOs and JSON payloads clean and immutable), modern Pattern Matching, and Spring Boot 4's lightweight non-blocking execution. The entire backend is organized into 20 strictly separated domain packages.

📨

Why Apache Kafka 3.7 in KRaft Mode? Event Streaming

Operations like AI blueprint synthesis, GitHub repository creation, and CI runner tests take between 10 to 60 seconds. A synchronous REST call would block HTTP server threads. I implemented Kafka KRaft (zero Zookeeper dependency) to publish domain events to partitioned topics and process them asynchronously.

⚡

Why Redis 7 Sliding-Window Rate Limiter? DDoS Guard

To prevent token minting brute-force and submission spam, I built a Redis sliding-window limiter using atomic INCR and EXPIRE. It includes Graceful Degradation: if Redis temporarily crashes, the filter logs a warning and allows requests through so candidates aren't blocked.

🗄️

Why MySQL 8.4 + Flyway Migrations? Relational Storage

Assessment scores and candidate submissions require strict relational integrity. I used Flyway migrations (V1__init_schema.sql) across 12 tables to guarantee zero drift between development and production databases.

🌐

Why Nginx Gateway on Port 80? Reverse Proxy

The backend is shielded behind an Nginx reverse proxy. It enforces dual-zone rate limiting (150 r/m API, 30 r/m Auth), gzip compression over 1024 bytes, and allows up to 50MB client body size to support large code commits.

💡 Tricky Architecture Questions & Sharp Answers

Click any question below to see the exact answer you should give:

Q1: What if a candidate uses ChatGPT to write the whole project?
Answer: "That's why I designed the Stage 11 personalized MCQ engine! After the code is submitted, our AI parses the candidate's exact commit and generates 12–15 multiple-choice questions citing their actual classes, methods, and architectural choices (e.g. 'Why did you put @Transactional on line 45?'). If a candidate had someone else or ChatGPT write the code, they won't be able to answer questions about their own implementation decisions."
Q2: How do you stop candidates from pushing commits after the deadline?
Answer: "I implemented an Atomic Freeze Order in SubmissionService.java:
  1. First, downgrade the candidate's collaborator permission from push to pull (Read-Only).
  2. Second, read the branch HEAD commit SHA.
  3. Third, create an immutable Git tag refs/tags/submission-SUB-XXXX at that SHA.
Because write permissions are revoked before reading the SHA, there is zero window for a candidate to push between reading and tagging."
Q3: What if the candidate modifies .github/workflows/ci.yml to fake 100% tests passed?
Answer: "Candidate CI is completely untrusted! Their repository workflow holds zero secrets and its results are only shown on the candidate dashboard as personal feedback. Official scoring runs inside our platform-owned private repository (evaluation-runner) which executes proprietary hidden tests and sends HMAC-SHA256 signed callbacks back to our API."
Q4: What happens if Redis crashes? Does the entire assessment stop?
Answer: "No! In RedisRateLimiter.java, I wrapped all Redis operations in a try-catch block with graceful degradation. If Redis is unreachable, the exception is caught, a warning is logged, and the request is permitted through so that an infrastructure cache glitch never ruins a candidate's timed test."

Under the Hood: Persists initial entity records with unique UUIDs. Emits REQUIREMENT_ANALYSIS_REQUESTED to assessment.pipeline.events topic for asynchronous background processing.

2

Anthropic Claude processes the Job Description against the Candidate Resume using the requirement-analysis.md prompt template to build a personalized skill breakdown.

Under the Hood: Synthesizes a 4-pillar Competency Matrix (Languages, Frameworks, Architecture, Cloud) and identifies exact skill gaps to test in the project.
KAFKA Event: REQUIREMENT_ANALYSIS_COMPLETED

Admin ➔ NGINX ➔ Spring Boot CONFIGURED

The recruiter customizes time limits (e.g., 48 hours), difficulty tier, required frameworks, and hidden test strictness before generating the project.

Under the Hood: Updates assignment parameters and stores customized weightings for hidden unit tests, architecture quality, and code-specific MCQs.
PUT /api/v1/admin/assignments/{id}/configuration

📝 AI Project Blueprint Synthesis
Spring Boot ➔ Claude AI ➔ MySQL STATUS: BLUEPRINT_DRAFT

Claude AI generates a complete, tailored production microservice specification based on blueprint.md with zero plagiarism risk.

🔒 Tamper-Proof Submission Lock
Candidate ➔ Spring Boot ➔ GitHub API STATUS: EVALUATING

Candidate clicks "Submit Project". The platform locks the repository permanently to prevent any post-submission modifications.

Critical Security Sequence:
  1. Revoke candidate write collaborator permission on GitHub API
  2. Query GitHub API for branch HEAD commit SHA
  3. Create immutable Git tag submission-SUB-XXXX at that exact SHA

📦 Who Does What: Low-Level Domain Packages

Clear breakdown of the 20 packages and what each class is responsible for:

intake/ Package

IntakeService.java: Ingests ATS requests, persists Company/Job/Candidate entities, and mints public ASSIGN-XXXX IDs.

blueprint/ Package

BlueprintService.java: Handles AI architecture synthesis, versioned drafts, manual edits, and 1-click approvals.

generation/ Package

ProjectGenerator.java: Merges blueprint specs with vetted templates to generate runnable starter code and Markdown docs.

github/ Package

GitHubClient.java: Creates private GitHub repos, commits skeleton code, manages candidate access, and sets rulesets.

submission/ Package

SubmissionService.java: Executes atomic commit freeze. DeadlineScheduler.java auto-submits overdue tests.

mcq/ Package

McqService.java: Generates 12–15 code-based MCQs, cryptographically shuffles options, handles 30-min timer, and grades responses.
